# Qwen local editing assessment

Researched 2026-09-10. **Recommendation B: possible, but postpone.** External/manual editing already solves the current production need. This is a researched future candidate, not an installation or inference proposal to execute now. No Qwen weights, custom nodes or Python packages were downloaded or installed; only documentation, metadata and source text were inspected.

## Candidate and provenance

Use **Qwen-Image-Edit-2511**, with Unsloth's **`qwen-image-edit-2511-Q4_K_S.gguf`**, if this investigation is later revived. The official Qwen catalogue and [upstream editing model](https://huggingface.co/Qwen/Qwen-Image-Edit-2511) identify 2511 as the downloadable editing release verified here. Qwen-Image-2512 is a text-to-image release; it must not be mistaken for a newer Edit checkpoint. Newer hosted Qwen announcements do not establish a downloadable local replacement.

The [Unsloth distribution](https://huggingface.co/unsloth/Qwen-Image-Edit-2511-GGUF) identifies that upstream model and city96 conversion tooling. Q4_K_S is selected here to minimize Q4-class footprint; Q4_K_M is 834,011,136 bytes larger. This is a hardware-first research choice, not proof that Q4_K_S preserves tiny edits as well as Q4_K_M or BF16. The model still has approximately 20 billion parameters: “Q4” does not make it a small model.

The [portable inventory](../tools/comfyui/qwen-model-candidate.json) records exact source revisions, upstream-advertised SHA-256 hashes and byte counts. These are metadata-verified hashes, **not local payload verification**, because no weights were acquired. Its upstream revisions identify the official snapshots inspected; they do not prove which exact upstream revision the quantizer used internally.

Total prospective payload is **18.804 GB / 17.512 GiB**, including **6.393 GB** of auxiliary weights. Existing T5, CLIP-L and Flux AE cannot replace these components. The official [ComfyUI guide](https://docs.comfy.org/tutorials/image/qwen/qwen-image-edit-2511) supplies a native baseline; its FP8 encoder is 9,384,670,680 bytes, so using that instead of the quantized encoder/projector raises this package to 22,049,224,414 bytes. BF16 diffusion is not the proposed path.

The [Unsloth guide](https://unsloth.ai/docs/models/tutorials/qwen-image-2512.md) documents the GGUF encoder plus separate vision tower, including a 2511 editing variant. Store the projector as **`Qwen2.5-VL-7B-Instruct-mmproj-BF16.gguf`**, beside the encoder, so automatic matching works. This is an explicit destination-name change, not a different payload. Only metadata was fetched here. If approved later, acquire exact files directly to destination-volume partials, verify them and avoid duplicate HF caches. Allow roughly 25–30 GB additional disk space for the 18.8 GB package and small evaluation artifacts; whole-repository downloads are unnecessary.

## Installed ComfyUI compatibility

Read-only inspection of the active conventional installation found **ComfyUI 0.18.1**, core `31283d2892f54caf9bfdf6edb9c98cbfa88c5f0c`, Python 3.14.3 and PyTorch 2.11.0+cu128. Machine paths and discovery logs remain outside Git. The separate portable installation was not touched.

Available core schemas include `TextEncodeQwenImageEditPlus`, `TextEncodeQwenImageEdit`, `ModelSamplingAuraFlow`, `CFGNorm`, `CLIPLoader` with `qwen_image`, and normal VAE/image/sampler nodes. Native Qwen editing is therefore present; a blanket ComfyUI upgrade is not justified by the inspection.

**Missing:** `UnetLoaderGGUF`, `CLIPLoaderGGUF`, the ComfyUI-GGUF node directory, and the Python `gguf` package. The node pack at revision **`6ea2651e7df66d7585f6ffee804b20e92fb38b8a`** supports `qwen_image` diffusion and `qwen2vl` encoder/vision loading. Its required local core APIs were found by source inspection. This is static compatibility evidence, not an import or execution test.

If later approved, the change would be installation of that reviewed node revision and a pinned `gguf` dependency into the **active** Python environment, followed by an owner-coordinated ComfyUI restart and schema validation. Its requirements specify `gguf>=0.13.0`; current PyPI metadata shows 0.19.0, Python >=3.10. Installed NumPy, sentencepiece and protobuf were identified; a future dependency review must check all transitive requirements before modifying the shared environment. No Torch, driver, Python or core upgrade is currently proposed.

Use `UnetLoaderGGUF` and `CLIPLoaderGGUF` (`qwen_image`), retaining existing native memory management. The loader discovers the projector by filename and dequantizes the encoder embedding tensor; therefore neither compressed file size nor RAM+VRAM addition is a reliable peak-memory formula. The optional Lightning LoRA is excluded: it adds a payload and a distillation variable, and GGUF LoRA loading is marked experimental by its maintainer. A 4-step speed claim must not be applied to the unmodified base model.

## Hardware fit and honest uncertainty

The following are **planning estimates/inferences**, not benchmarks or new hard gates. No reputable exact RTX 4070 / Windows / 32 GB measurement for this four-file combination was verified.

| Factor     | Assessment                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VRAM       | Roughly **8–10 GiB working allocation** with staged loading and partial CPU offload; transients may exceed this. The 11.56 GiB diffusion file alone cannot stay fully resident alongside Windows, reserved VRAM, activations and auxiliary models.                                                                                                                                                                                                    |
| Host RAM   | Allow roughly **16–24 GiB for the ML working set**, with total system pressure potentially approaching or exceeding **24–32 GiB** depending on desktop use, mappings, caches and dequantization. Q4 can work in principle, but comfortable coexistence with normal development is unproven. These ranges are not requirements to chase by closing apps.                                                                                               |
| Offload    | Necessary; keep the existing automatic offload/reservation strategy. Extra PCIe transfers and GGUF dequantization can make a smaller checkpoint slower.                                                                                                                                                                                                                                                                                               |
| Speed      | Budget **several minutes to tens of minutes** for a 40-step base-model edit; **5–20 minutes** is a scheduling allowance, with additional cold loading, not an RTX 4070 benchmark. Paging can make it worse. The guide's illustrative one-minute text-to-image timing is not evidence for this machine/edit.                                                                                                                                           |
| Resolution | Retain the same 1448×1086 source, approved crop and proposed **1120×784** output for comparability, batch 1. This is below one megapixel, not a verified maximum. The installed EditPlus node internally builds a roughly 384² vision view and roughly 1024²-area VAE reference; those reference dimensions must be recorded in any future graph rather than assuming all paths use 1120×784. Avoid larger images and multi-reference work initially. |
| Quality    | Q4 trades precision for memory; encoder quantization can also affect instruction following. Fine wall texture, poster lettering and unchanged geometry are exactly the details that need review. No preserved-pixel guarantee or Qwen-versus-Kontext ranking exists.                                                                                                                                                                                  |

The upstream base example uses 40 steps and true CFG 4; freeze and review Qwen-specific settings before any future run.

Retain raw output and normalized no-edit control, report all internal/output dimensions, and compare target close-ups, fixed landmarks and outside-ROI differences. Apply identical 320-pixel / 64-colour / contrast 1.15 / exact 640-display processing. No compositing or cleanup may hide drift. Every image remains a draft pending human review.

**Decision B:** preserve this inventory, continue art production through the interchangeable external/manual path, and revisit local editing only when it solves a concrete recurring cost, privacy or availability problem. The extra installation, roughly 18.8 GB acquisition and uncertain shared-host fit do not justify another benchmark cycle now. No download, installation, restart or inference is authorized by this document.
