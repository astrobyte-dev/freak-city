## RTX 4070 / 32 GB memory and timing plan

Use one source image, **1120 × 784**, **20 steps**, FP8 diffusion/T5, native automatic partial GPU loading and CPU offload. Keep the existing 1.5 GB VRAM reservation and RAM-pressure cache settings. The diffusion file alone is roughly 11.1 GiB, before reference latents/activations/encoders/VAE, so it cannot all fit alongside this workstation's existing GPU use. The workflow's text-encoder device remains `default` to use the installed loader's normal management.

**Planning estimates, not measured results:** roughly **8–10 GiB GPU working allocation**, **16–24 GiB ComfyUI host working set**, and **24–30 GiB total system RAM** under a suitably quiet desktop. Budget **2–10 minutes per 20-step image**, with roughly **30–120 seconds additional cold loading**; heavy paging, thermal state or CPU offload can exceed that range or cause OOM. A fixed seed is not a performance or byte-reproducibility guarantee.

Current host headroom is inadequate for a confident first load. Before a future approved run, have the owner free roughly **20 GiB available host RAM** and confirm no competing GPU job; do not close applications automatically. The estimates can fail on a 32 GB machine. Do not force high-VRAM mode, disable safeguards or add another GPU process. If memory pressure is excessive, stop and report the failure; changes such as a different quantization, resolution, tiled VAE or launch settings require a revised explicit proposal. None is silently included in this approval request.

Separate cold model loading, graph execution and steady sampling in measurements. Poll dedicated GPU memory and process/system RAM during a future authorized run without resetting global counters for another job. Retain whether peak values are sampled or framework-reported; polling can miss brief peaks. Queue metadata and per-run output-prefix identifiers keep the experiment distinguishable from another project's work.
